# M0 可靠性实施记录（2026-10-30）

本记录对应 [非 3D 功能实施路线图](maoxiang-implementation-roadmap-20261030.md) 的 A、B 工作包。当前是实现与验证记录，**尚未满足 M0 全部出口条件**；下列未完成项和真机验证完成之前不将 M0 标为已验收。

## 本次实现

- 数据库从 v5 显式迁移到 v6，保留原始无归属窗口并在记忆页面提供查看和确认丢弃入口。新待提炼回合按角色、会话和回合关联消息边界，画像与事件独立领取、确认和重试；领取有租约，会话版本阻止回溯后的旧结果提交。
- 每个回复泡、会话摘要与截至该泡的记忆素材共同提交；中断的部分回合可在重新打开数据库后恢复。回溯按来源处理素材和事件、重建部分保留的多泡回合，并把受影响的已保存心声和朋友圈标为可能过时。
- 手动与自动生成分别调度；自动任务再次检查开关、开关代次与日期。心声和朋友圈按角色及日期去重，手动请求不受每日自动限制。生成结果与请求关联在同一事务提交，配图处理中断可恢复，失败时保留文字并提示；手动任务页面从 WorkManager 恢复状态。
- 朋友圈空态遵守日更开关；未实现的生成类型不再报告成功。聊天模式改为每次请求显式传递，避免 IM 与手机聊天的共享状态互相覆盖。

## 未完成或待验证

- 任务历史仍依赖 WorkManager，尚无完整持久化任务历史及逐类失败原因；网络、鉴权和解析失败目前主要使用统一提示，自动任务失败没有独立历史页面。需要补足取消、重试和重启恢复的受控 WorkManager 测试。
- 配图失败已提示但缺少单独补图重试及分类型图片设置；通知与系统投递不能同数据库原子提交，稳定通知 ID 可减少重复，但不能保证只提醒一次或在权限变化后重新投递。
- 事件提炼以批次记录来源边界，而非模型输出中每个事实的精确来源；回溯批次内部时可能保守地移除并重新提炼部分事件。历史版本已消费且未留来源的素材无法可靠重建或归属。
- 后台主动消息仍是原有简化扫描和兜底逻辑，完整会话频控、失败语义及回归展示属于 D；其在途消息与其他生成路径仍需在真实设备上验证。
- 仍需按路线图在设备上完成双角色和 IM／手机交错聊天、前后台并发总结、单通道失败重试、升级与回溯、关闭自动生成、断网恢复、图片失败和通知权限等端到端检查，并记录模型及结果。
