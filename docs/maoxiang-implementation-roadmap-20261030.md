# GouXiang 非 3D 功能实施路线图

> 基准日期：2026-10-30；代码基准：`5bb8e08`（后台生成基建 M0/M1）。这是基于当前源码的实施建议，不是功能已验收声明。
>
> 输入：[猫箱功能总分析](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang-feature-analysis.md)、[01～12 专项文档](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang)和 [UI 页面索引](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang/ui/README.md)。本工程：[GouXiang](../)。
>
> 适用范围：保留二维图文、聊天和语音形态；不实施 VRM、3D 房间和 3D 演出。商业化及社区没有被用户排除，单独列为后续决策，不当作已批准放弃。

## 1. 结论与排序

先保证现有聊天和生成不会串角色、丢数据或误报成功，再完善角色创建与主动陪伴，随后建设可复用的二维内容生成管线，最后扩展社交、音频和剧情。优先级综合用户价值、现有功能暴露的问题、依赖关系和投入，不代表原文档中的 P0/P1。

| 顺序 | 工作包 | 优先级 | 为什么先做 | 完成标志 |
|---|---|---|---|---|
| 1 | A：记忆隔离、回溯与并发安全 | P0 | 关系到多角色数据正确性，其他玩法也依赖记忆 | 交错角色、并发总结、回溯和升级均不串数据、不丢新消息 |
| 2 | B：后台生成与现有页面可靠性 | P0 | 当前后台任务与页面已向用户暴露 | 任务状态真实、开关生效、失败可见且可恢复 |
| 3 | C：角色创建与管理 MVP | P1 | 让用户从固定种子角色走向自己创建的陪伴角色 | 手动创建、编辑、保存并开始聊天的闭环可用 |
| 4 | D：主动消息与离线回归 | P1 | 补齐文档的核心陪伴场景，复用现有调度和聊天 | 合理频率的离线消息可持久化、回归呈现、通知且不重复 |
| 5 | E：记忆召回与状态面板 | P1 | 长期陪伴质量和角色状态直接影响聊天体验 | 当前话题召回相关记忆；角色状态有可追溯记录与回溯处理 |
| 6 | F：图文内容管线、番外与心动事件 | P1 | 提供高感知的新玩法，公共底座可复用 | 一组可选番外模板及三个心动事件完整可用 |
| 7 | G：手帐、小说、合照与心声完善 | P2 | 在图文管线稳定后，以较低重复投入扩展内容 | 四类内容有各自入口、记录、失败恢复及历史联动 |
| 8 | H：朋友圈扩展与发现 | P2 | 从单角色时间线扩展到用户发帖和多角色互动 | 权限生效，用户和角色可在同一时间线互动 |
| 9 | I：语音通话升级与广播剧 | P2 | 已有语音底座，但实时语音和长音频工程量较大 | 通话目标明确；广播剧从脚本到后台播放可用 |
| 10 | J：二维 AVG 剧情 | P3 | 是独立玩法和状态引擎，依赖内容及历史能力 | 章节、选项、存档、回溯和结局可完整体验 |
| 11 | K：商业化、社区和创作者生态 | P3／待决策 | 文档涉及，但本地产品范围和运营方式尚未确定 | 先明确业务边界，再安排实现；不以占位模拟完成 |

P0、P1 指推荐的交付顺序；P2、P3 并非必须等所有同级任务结束才可并行。A 是 C～J 的共同数据前置，B 中的任务可靠性是 D、F、G、I 的前置；D 与 C 可在 A/B 完成后并行。`S/M/L` 在下文仅表示相对复杂度，不是工期承诺。

## 3. 公共实施约束

1. **以现有工程为准**：复用当前 Room、Compose、LLM/生图/语音适配器、Worker 和通知；原文面向 AIAvatar-SDK 的模块名、工具注册缝和人日估算不直接搬用。协议分隔符等实现细节只在影响互通或可见行为时优先处理。
2. **持久化与升级**：数据库当前为 v5。每次 schema 调整提供显式 Room migration，保留角色、聊天和已生成内容；覆盖旧版升级与迁移失败场景。任何不能确定来源的历史数据都不得猜测归属。
3. **任务真实可追踪**：用户手动请求和自动任务记录来源、角色、会话、请求 ID、状态、失败原因、时间和结果 ID；`queued/running/succeeded/failed/cancelled` 要与实际结果一致。任务关联稳定幂等键，任务完成、取消、重试和进程恢复后不能重复生成或误报成功。网络请求不能放在数据库事务中。
4. **开关与资源消耗**：自动任务在调度及执行前检查开关；关掉后阻止尚未开始的自动请求，已开始的请求说明取消语义。手动请求按按钮本身的意图执行。不同类型的可选图像生成和通知遵循各自设置；不给无功能的开关制造成功假象。
5. **历史一致性**：聊天修改、回溯、重生成涉及的待处理素材和异步产物，记录来源消息范围及会话版本；提交结果前验证版本，过期产物标记失效或待确认，不得重新写入已回溯历史。历史记录和数据库变动尽可能以事务收口。
6. **失败与降级**：网络、鉴权、超时、解析失败和用户取消应可区分；不把兜底文案当成真实生成成功。图像失败可保留文字成品并明确提示；无可用模型时提供配置入口和可重试状态。
7. **LLM 输出不等于可信数据**：按各功能的 schema 校验、限制长度和数量；解析失败不污染正式记录；不在日志或通知里输出密钥和完整私人聊天。成本、频率、安静时段的参数先作为本地可配置默认，不宣称是猫箱服务端真实值。

## 4. 分工作包落地

### A · 记忆隔离、回溯与并发安全（P0，L）

**现状依据**：[`pending_memory_window`](../app/src/main/java/com/neethu/gouxiang/data/MemoryEntity.kt) 只有单行 payload，`MemoryTurn` 无角色／会话字段；[隔夜任务](../app/src/main/java/com/neethu/gouxiang/work/DerivativeScheduler.kt)选择最近会话；[前台协调器](../app/src/main/java/com/neethu/gouxiang/chat/ChatMemoryCoordinator.kt)共享窗口且画像或总结任一成功即清除快照；后台成功后[清空整个窗口](../app/src/main/java/com/neethu/gouxiang/work/DerivativeExecutor.kt)。这些是源码推断的串角色或并发丢失风险，尚待复现。

**实施任务**

- [ ] A1. 为待处理回合增加稳定 `conversationId`、`characterId`、`turnId`、来源消息边界和顺序；保证同角色 IM／手机会话的来源可区分，记忆归属仍按角色隔离。调整 `MemoryWindowDao`、`RoomMemoryWindowStore`、协调器及所有调用方。
- [ ] A2. 统一前台、手动和隔夜入口：以短事务领取快照，在事务外调用 LLM 并先生成候选结果；完成后在同一事务内校验会话版本、写入记忆并按快照 ID 或游标确认已消费内容。加入租约／超时恢复，禁止两条入口同时消费同一通道同一段素材。请求期间新增的回合必须保留。
- [ ] A3. 画像与事件总结分别记录进度和失败状态；一侧失败不删除另一侧尚需的素材。写入侧设置幂等键或可靠去重，避免进程在落库后、确认前中断造成重复。
- [ ] A4. 回溯／重生成同步处理待提炼回合、来源事件和在途任务；用会话版本阻止旧请求完成后重新写回。保留与回溯点无关的画像和用户手工内容；按来源而非只靠生成时间决定事件影响范围。
- [ ] A5. 旧 v5 单行窗口没有可靠归属：迁移时原样备份为“来源不明，待处理”，不自动分配给最近角色；提供可见的查看／丢弃路径，或经用户确认后处理。既有角色、消息、已保存记忆不重建。
- [ ] A6. 新窗口采用能无损表示空字段与特殊字符的结构化格式；旧 `deserializeWindow` 会跳过用户文本为空的主动回合，迁移与读取时覆盖该边界，不能把主动回合误当损坏数据丢弃。

**验收**：两个角色交错聊天再分别总结；前台与隔夜同时运行；总结期间追加消息；只让画像或事件一侧失败后重试；回溯期间让旧请求晚到；重启及 v5 升级。以上均不串角色、不丢新增回合、不重复写入，也不复活回溯内容。

### B · 后台生成与现有页面可靠性（P0，M～L）

**现状依据**：[`DerivativeScheduler`](../app/src/main/java/com/neethu/gouxiang/work/DerivativeScheduler.kt) 与 [`DerivativeWorker`](../app/src/main/java/com/neethu/gouxiang/work/DerivativeWorker.kt) 已存在，但一次性任务缺少自动／手动来源；朋友圈日戳在入队之前写入；[执行器](../app/src/main/java/com/neethu/gouxiang/work/DerivativeExecutor.kt)对当天已有动态直接返回成功，因此同日手动生成也会被跳过。朋友圈页面空态还会自动生成，即使设置页写的是关闭后仅手动生成，见 [`openMoments`](../app/src/main/java/com/neethu/gouxiang/ui/MainViewModel.kt)。心声周期扫描没有按日去重，需避免仅凭注释认定去重已生效。

**实施任务**

- [ ] B1. 扩展现有任务参数和持久化状态，区分 `manual`／`automatic`；自动任务执行前二次查开关。关闭开关时取消或跳过未开始的自动任务，不能误取消用户主动任务。明确已执行请求与通知开关的行为。
- [ ] B2. 按角色／任务／本地日期对自动心声和日更做持久化幂等；仅在成功后记录完成。朋友圈的手动生成不受“每日一次自动”限制；若产品另设限制则明确告知。避免全局日期戳使部分角色漏发。
- [ ] B3. 修正首进朋友圈空态自动生成与开关说明的冲突：自动关闭时展示空态及手动按钮；自动开启时走受控自动路径。进页、重进、重启均不重复触发。
- [ ] B4. 将成功、失败、跳过、取消与重试区分；针对无实现的类型禁用入口或明确“开发中”，不能返回假成功。状态以持久化数据为准，进程重启后 UI 可恢复；通知跳转到对应结果，权限拒绝不影响内容保存。
- [ ] B5. 审视心声／朋友圈生成后图片回填失败、通知与结果落库的中断点；按请求 ID 幂等恢复，避免重试重复插卡或静默吞错。
- [ ] B6. 移除 `ChatContextBuilder.phoneStyle` 进程级可变开关，将聊天形态显式传入每次请求；目前前台聊天与后台主动消息都可能临时修改该值，并发执行可能使用错误的提示词。覆盖 IM 与手机模式同时生成的测试。

**验收**：关闭自动项后进入空朋友圈与触发周期任务不发请求；手动点击仍可生成；同一天手动两次的结果与 UI 说明一致；模拟断网、进程重启、重复调度、通知权限拒绝和中断恢复，记录与结果数量一致。

### C · 角色创建与管理 MVP（P1，M～L）

**现状依据**：已有 [`CharacterEntity`](../app/src/main/java/com/neethu/gouxiang/data/CharacterEntity.kt)、角色主页与头像生成，但“创作 AI+”是占位页；[01 专项](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang/01-character-card.md)覆盖创建、字段、形象、音色及导入导出。

- [ ] C1. 先实现手动创建／编辑：名称、角色设定、简介、示例台词、开场白、形象描述和风格；必填、长度、空白与重复名称提示明确；支持本地草稿和预览。
- [ ] C2. 保存角色、建立首个 IM 会话与开场白的原子流程；从列表／主页可打开、续聊。角色与会话通过 ID 关联，新增角色不重置种子或已有历史；同时提供手机聊天会话的创建或进入路径，验证首页更新时序。
- [ ] C3. 接入现有二维头像生图，显示生成中、失败和重试；风格词生效；改写形象后生成新文件或使用版本化缓存键，避免旧头像被错误复用。明确“设为当前”及本地图片管理。
- [ ] C4. 第二步增加 AI 辅助填表、角色卡导入导出及兼容校验；保留纯手动路径。角色绑定音色、更多生图风格／参考图及完整图库作为后续增量，按适配器实际支持能力显示。

**验收**：创建两个不同角色、修改其字段并分别聊天，重启后角色／头像／会话仍对应；无模型或生图失败也可保存手工卡；重复点击保存不创建重复会话。

### D · 主动消息与离线回归（P1，L）

**现状依据**：[`ProactiveMessages`](../app/src/main/java/com/neethu/gouxiang/protocol/ProactiveMessages.kt)提供首次／2 小时／12 小时简化触发，[Worker](../app/src/main/java/com/neethu/gouxiang/work/DerivativeExecutor.kt)直接将消息落入会话，并按命中会话计通知数。[05 专项](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang/05-proactive-messages.md)建议待消费队列、频控、回归呈现与通知。WorkManager 是尽力调度，不能承诺精确时刻或被强制停止时持续运行。

- [ ] D1. 按会话保存活跃时间、最近主动消息、批次、消息 ID 和未读／已读状态；可新增 outbox，也可扩展消息表，但“生成、展示、消费”状态必须可区分，保留当前消息及迁移兼容。
- [ ] D2. 定义自动触发与回归策略：最小间隔、每日上限、安静时段、回归批次上限、在线输入时避让；所有数值作为本地可配置默认，不硬称猫箱原始参数。后台周期扫描与前台进页共用会话级事务预约、阈值和幂等门禁；处理扫描上限，避免会话较多时旧会话长期漏扫。
- [ ] D3. 生成结果区分真实成功、网络失败及有意的模板降级；失败可重试，不能因未抛异常就记作真实成功。通知统计实际新消息数，并在多会话时跳正确目标或消息列表。
- [ ] D4. 回归时展示离线分隔及有序消息；已存消息不能重复回放或重复通知；处理用户中途发送、回溯、关闭自动开关和进程重启。保留对通知权限关闭的应用内查看路径。
- [ ] D5. 首次主动消息场景移除硬编码角色名“小唐”，使用当前角色或中性文案；自建角色与种子角色均不得串名。

**验收**：模拟多会话、后台重复执行、失败后重试与进页同时触发；检查消息数、通知数、顺序、已读状态一致；安静时段和日上限生效，用户恢复聊天时不重复轰炸。

### E · 相关记忆召回与状态面板（P1，M～L）

**现状依据**：[`MemoryInjection.block`](../app/src/main/java/com/neethu/gouxiang/chat/MemoryInjection.kt)接收 query 但没有用它筛选事件；[`StatusRule`](../app/src/main/java/com/neethu/gouxiang/chat/StatusRule.kt)是规则状态条。文档分别要求相关记忆与[状态生成、记录和回溯](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang/08-status-system.md)。

- [ ] E1. 在角色隔离前提下，以话题相关性、重要性和时间做有界召回；优先实现可解释的本地关键词／时间回退，向量检索为可选增强，不让服务不可用阻断聊天。画像、事件和渐忘记忆分别限制注入预算。
- [ ] E2. 建立角色状态记录，至少包含心情、正在做的事、内心想法、来源范围、生成时间与版本；定时／回合结束更新，失败保持最近有效状态，规则状态作为无记录时的兜底。
- [ ] E3. 聊天状态条接状态面板，支持查看近期状态和来源；回溯后标记或清除受影响状态，避免过期任务回写。

**验收**：向两个角色写入不同事件后分别查询，相关事件优先且无跨角色泄漏；无检索服务仍能聊天；生成失败与回溯后状态保持一致。

### F · 图文内容管线、番外剧场和心动事件（P1，L）

**现状依据**：[06 专项](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang/06-sidestory-theater.md)的 P0 提议 15 个图文模板，[09 专项](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang/09-heartbeat-mode.md)定义查手机、查状态、吃醋等事件；现有“心动模式”仅是对话风格。总文档与专项对模板总数统计口径不同，先以专项 P0 内容作为选材，不用固定总数判断完成。

- [ ] F1. 在 B 的任务能力上新增统一内容记录：类型、角色／会话、来源消息范围、版本、模板 ID、状态、结构化文本、图片文件和时间；支持列表、详情、删除、生成中、失败重试及通知。只抽取确实共用的部分，保留现有心声数据兼容。
- [ ] F2. 建立版本化的本地二维剧场模板目录、输入校验和输出 schema；首批实现 5 个不同类型的可用模板，体验稳定后扩到文档建议的 15 个。每个模板需有具体 prompt、标题、正文和可选配图；不是只录标题。

- [ ] F4. 在同一管线上实现“查手机、查状态、让 TA 吃醋”三个心动事件：独立输入与结果展示、事件记录及失败恢复；查状态复用 E 的状态信息。后续增加礼物、日记、前世、主页和惊喜剧场，避免与聊天风格同名混淆。
- [ ] F5. 后续按文档需求增加多人模板及惊喜抽取；批量任务必须可取消、有进度和幂等，不能一次性无提示触发大量请求。LLM 工具主动调用属于可选扩展，先让用户入口闭环。

**验收**：五个模板及三个事件各至少一次完整生成／重启查看／删除；同一角色来源正确；图像失败仍能查看文本；重复提交、回溯与取消后不会生成重复或过期记录。

## 5. 交付里程碑与验收方式

| 里程碑 | 内容 | 出口条件 |
|---|---|---|
| M0：可靠性 | A + B | 旧库升级成功；双角色记忆隔离、前后台并发和任务开关通过；已有聊天、心声、朋友圈不回归 |
| M1：用户可创造和被陪伴 | C + D + E | 新建角色可聊天；离线消息和状态可控、可解释、可恢复；日常使用无明显数据错乱 |
| M2：内容玩法 | F | 5 个番外模板 + 3 个心动事件完成端到端；再扩展到 15 个模板 |
| M3：内容和社交扩展 | G + H | 四类衍生内容、用户发帖和角色权限完成各自闭环 |
| M4：长音频与剧情 | I + J | 广播剧后台播放及示例剧情存档回溯通过 |
| M5：产品扩展 | K | 先形成明确的商业／社区决策与独立方案，再排期 |

验收以可复现结果为准：

1. **自动化**：针对数据隔离、事务边界、回溯版本、失败恢复、频控、幂等、解析和状态机写行为测试；Room 做旧版升级测试；后台调度使用可控时钟和 WorkManager 测试环境。现有聊天与协议测试继续运行。
2. **端到端**：至少在一台 Android 真机或模拟器验证角色创建、聊天、断网恢复、后台生成、通知授权／拒绝、进程重启、回溯及相关内容查看；列明机型、系统、模型、结果和已知限制。
3. **AI 质量**：记录模型和配置，抽样检查角色一致性、来源正确性、格式、失败提示与成本；不要把一次模型生成成功当作稳定性证明。
4. **UI 对照**：对照 [UI 索引](/home/neethu/projects/AIAvatar-SDK/docs/maoxiang/ui/README.md)逐页检查可访问入口和交互；部分原页面由 Lynx 下发且截图受限，视觉一致性需实际运行对照，不能仅凭资源静态判断。
5. **交付记录**：每个工作包标注代码提交、迁移版本、测试命令、真机结果、未完成边界。未做运行验证的风险保留为“待复现”，不写成已证实故障。
